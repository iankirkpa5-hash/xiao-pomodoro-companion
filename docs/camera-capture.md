# On-Demand Single-Frame Camera Capture (`feature/camera-capture`)

Status: **Implemented and host-verified; pending real-device verification.**

This experimental branch adds on-demand single-frame JPEG capture over USB serial
on top of the current `v1.6` Pomodoro + microphone + PCM mainline. It does **not**
enable the camera at boot, does **not** add camera UI to the Round Display, does
**not** change microphone thresholds or `platformio.ini`, and does **not** claim
the `v1.7-camera-test` thermal issue is solved.

## Safety And Thermal Boundaries

- **Off by default at boot**: `setup()` never initializes the camera. If the camera
  module is removed or idle, no camera I2C/SCCB traffic, XCLK PWM, or PSRAM
  allocation occurs.
- **Immediate deinit after single frame**: `CAM CAPTURE <id>` initializes the
  OV2640 (`FRAMESIZE_QVGA`, `PIXFORMAT_JPEG`, `LEDC_CHANNEL_1` / `LEDC_TIMER_1`),
  waits 250 ms for initial exposure settling, captures one frame, copies the raw
  JPEG bytes into a bounded PSRAM buffer (max 128 KiB), returns the frame buffer,
  and calls `esp_camera_deinit()` before replying `CAM STATE ... READY`. Every
  error path after `esp_camera_init()` also returns any acquired frame buffer and
  calls `esp_camera_deinit()`.
- **Hardware limitation**: on the XIAO ESP32S3 Sense, `PWDN` and `RESET` are `-1`
  (not wired to ESP32S3 GPIOs). Calling `esp_camera_deinit()` stops the driver
  and XCLK, but does **not** prove the sensor power rail is switched off. Monitor
  board temperature by touch and disconnect power immediately if it reaches
  uncomfortable heat (Grade 3+).
- **No overlap with active PCM recording**: `CAM CAPTURE` returns `BUSY` while a
  `PCM` recording session holds a buffer, and `CAM INFO` remains completely
  passive.

## Capture Workflow (Real Device)

Attach the removable camera module to the Sense expansion board FPC connector
(with USB power disconnected while plugging/unplugging the ribbon). The Round
Display is **not** required for camera capture: `TOUCH_INT` uses `INPUT_PULLUP`
so detached touch stays idle, and SPI display writes do not block boot. Close
other serial monitors and disconnect the Microphone Web Monitor first.

### Option A: Local Browser Viewer (Web Serial)

For quick interactive framing and viewing in desktop Chrome or Edge:

```powershell
node tools/camera-monitor/serve.cjs
```

Open `http://127.0.0.1:8766`, click **連接 XIAO**, then click **拍一張**. See
[Camera Web Monitor](../tools/camera-monitor/README.md).

### Option B: CLI Evidence Capture

From the repository root:

```powershell
& "$env:USERPROFILE\.platformio\penv\Scripts\platformio.exe" run -t upload
& "$env:USERPROFILE\.platformio\penv\Scripts\python.exe" tools/capture_camera.py --port COM11 --notes "Desk lamp on; lens ~30 cm from object; camera attached for single-frame test"
```

On Linux/macOS, use `pio run -t upload` and `python3 tools/capture_camera.py --port /dev/ttyACM0`.

Each run creates a new Git-ignored `test-runs/cam-.../` directory containing:

| File | Meaning |
| --- | --- |
| `frame.jpg` | Bit-exact JPEG bytes from the device (verified with IEEE CRC32 and SOI/EOI checks) |
| `serial.log` | Original received USB serial bytes, including Pomodoro/Mic telemetry and diagnostics |
| `report.json` | Source hashes, tool hash, commands, metadata, SHA-256, diagnostics, and verdict |

A passing transfer (`PASS_CAMERA_CAPTURE`) proves serial integrity only. Separately
inspect `frame.jpg` visually, check module warmth, and verify display, touch,
Settings, Bright, and microphone operation.

## Serial Protocol V1 (`CAM`)

Numbers are decimal except CRCs (8 lowercase hex digits, IEEE 802.3 CRC32 matching
Python `zlib.crc32`) and chunk hex payloads. Lines end with LF (CRLF accepted).
The session ID is a nonzero `uint32_t` generated by the host. Protocol replies
begin with `CAM `; existing `PCM ` and Pomodoro/Mic telemetry continue
independently on the shared serial router (`src/serial_commands.cpp`).

```text
CAM INFO
CAM INFO 1 320 240 JPEG 131072 64 <free_psram_bytes>

CAM CAPTURE <id>
CAM STATE <id> READY <length_bytes> <width> <height> <format> <capture_ms> <crc32>

CAM STATUS <id>
CAM STATE <id> READY <length_bytes> <width> <height> <format> <capture_ms> <crc32>

CAM READ <id> <offset_bytes>
CAM DATA <id> <offset_bytes> <jpeg_hex> <chunk_crc32>

CAM RELEASE <id>
CAM RELEASED <id>

CAM ERROR <id_or_0> <reason>
```

Error reasons: `BAD_COMMAND`, `BUSY`, `NO_PSRAM`, `INIT_FAILED`, `CAPTURE_FAILED`,
`BAD_FRAME`, `FRAME_TOO_LARGE`, `NO_CAPTURE`, `BAD_OFFSET`.

- `CAM CAPTURE` with the same active `<id>` is idempotent and returns the existing
  `READY` state without re-initializing the camera.
- `CAM RELEASE` is idempotent. If the host disappears, 60 seconds without session
  activity expires and frees the PSRAM buffer.
- `CAM READ` offsets must be multiples of 64 within `[0, length_bytes)`.
